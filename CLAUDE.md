## Project Overview

**Mark's Hobby Farm** is an e-commerce portfolio demonstration website showcasing what can be built for small working farms. This is a real, working site deployed on Mark Barney's hobby farm (653 Pudding Hill Road, Hampton, Connecticut) used to prospect other farm owners who want web presence.

**Key Context:**
- This is NOT a generic e-commerce template — it's a sales demonstration
- Portfolio quality matters; this site is shown to real farm customers
- Simplicity is intentional; small farmers don't want complexity
- Authenticity matters; use actual farm details (location, real products)
- Success criteria: Would a real farm customer be impressed?

See `README.md` and `STRIPE_INTEGRATION_PLAN.md` for full project context.

## Tech Stack

- **Frontend:** React 18 + TypeScript + Vite
- **Backend:** Express.js + TypeScript
- **Database:** PostgreSQL (Neon serverless) + Drizzle ORM
- **Authentication:** Google OAuth via Passport.js
- **Payments:** Stripe (with webhook integration)
- **Styling:** Tailwind CSS + PostCSS
- **Forms:** React Hook Form + Zod validation
- **UI Components:** Radix UI + custom components
- **Routing:** Wouter (lightweight client router)
- **Data Fetching:** TanStack React Query

## Database Schema

Three main tables:
- **users**: Google OAuth user accounts, Stripe customer IDs
- **products**: Farm products (eggs) with price (in cents), inventory, image
- **orders**: Customer orders with items (JSON), total price, Stripe payment intent ID, status

Items stored as JSON string in orders table: `[{productId, name, quantity, unitPrice}]`

## API Routes

All routes under `/api/`:

**Auth:**
- `GET /api/auth/google` — Initiate Google OAuth login
- `GET /api/auth/google/callback` — OAuth callback
- `GET /api/auth/me` — Get current user (returns null if not authenticated)
- `POST /api/auth/logout` — Logout

**Products:**
- `GET /api/products` — List all active products

**Orders:**
- `GET /api/orders` — Get authenticated user's orders
- `POST /api/orders` — Create new order

**Checkout:**
- `POST /api/stripe/checkout` — Create Stripe payment intent
- `POST /api/stripe/webhook` — Stripe webhook (raw body, signature verification)

## Important Implementation Patterns

**Authentication:**
- Google OAuth via Passport (configured in `server/auth.ts`)
- Session managed with `express-session` + PostgreSQL backend (`connect-pg-simple`)
- `isAuthenticated` middleware available for protected routes

**Database Access:**
- Use Drizzle ORM: `import { db } from "@/server/db.js"`
- Schema imported from `@shared/schema.js`
- Example: `await db.select().from(products).where(eq(products.id, productId))`

**Stripe Integration:**
- Payment intents created on `/api/stripe/checkout` (requires authenticated user + cart items)
- Webhook at `/api/stripe/webhook` handles payment confirmation
- Updates order status and inventory after successful payment
- Raw body capture for webhook signature verification (in `server/index.ts`)

**Price Handling:**
- All prices stored in cents (899 = $8.99)
- Convert to dollars when displaying: `(price / 100).toFixed(2)`

**Inventory:**
- Decremented when order is completed (via Stripe webhook)
- No pre-order reservations; inventory is final at payment completion

## Building & Deployment

**Production Build:**
1. Run `npm run build` → creates `dist/public/` (client) + `dist/server/` (server)
2. Set `NODE_ENV=production`
3. Set required env vars: `DATABASE_URL`, `STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
4. Run `npm start` → Express server serves both API and static frontend

Vite config specifies:
- Frontend root: `client/`
- Build output: `dist/public/`
- Server expects static files at `dist/public/`
- SPA fallback: all non-API routes serve `index.html`

- `DATABASE_URL` — Neon PostgreSQL connection string
- `STRIPE_SECRET_KEY` — Stripe secret key

## Common Development Tasks

**Add a new page:**
1. Create component in `client/src/pages/` (e.g., `client/src/pages/Returns.tsx`)
2. Add route in `client/src/App.tsx` using Wouter
3. Add navigation link in `client/src/components/Navbar.tsx`

**Add a new product field:**
1. Update schema in `shared/schema.ts` (add column to `products` table)
2. Run `npm run db:push` to migrate
3. Update seed script if needed: `scripts/seed-products.ts`
4. Update storage query in `server/storage.ts`
5. Update Product types/interfaces if sharing across client

**Add an API endpoint:**
1. Add route handler in `server/routes.ts`
2. Use `isAuthenticated` middleware if user auth required
3. Client calls via `fetch("/api/path")` or React Query
4. Test with `npm run dev`, make API calls from frontend

**Debug database:**
1. Run `npm run db:studio` to open Drizzle studio UI
2. Browse/edit tables, run queries interactively
3. No code needed; great for inspecting data

## Notable Implementation Details

**Session Storage:**
- Sessions stored in PostgreSQL via `connect-pg-simple`
- User object serialized/deserialized by Passport

**Cart Management:**
- Cart is client-side only (React state or localStorage)
- No server-side cart; items sent with checkout request
- Inventory check happens at payment time

**Order Workflow:**
1. User adds items to cart (client-side)
2. `POST /api/stripe/checkout` creates payment intent (server reserves nothing yet)
3. Stripe checkout modal (Stripe-hosted)
4. On successful payment, Stripe webhook fires `handleWebhook`
5. Webhook creates order, decrements inventory, updates payment status
6. Frontend polls or waits for confirmation

**Email Notifications:**
- Currently via Stripe-triggered emails (if enabled in Stripe dashboard)
- Future: implement email service for order confirmation/notifications
